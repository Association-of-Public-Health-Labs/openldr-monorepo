# Quickstart

This guide will get you up and running with the OpenLDR Analytics API. You'll learn how to authenticate, make your first request, and understand the common query parameters. {{ className: 'lead' }}

## Authentication {{ tag: 'POST', label: '/auth/login' }}

<Row>
  <Col>
    All API endpoints require authentication via a JWT Bearer token. To obtain a token, send a `POST` request to the `/auth/login` endpoint with your credentials.

    The response will include an `access_token` that you must include in the `Authorization` header of all subsequent requests.

    <Properties>
      <Property name="user_name" type="string">
        Your OpenLDR account username.
      </Property>
      <Property name="password" type="string">
        Your OpenLDR account password.
      </Property>
    </Properties>
  </Col>
  <Col sticky>
    <CodeGroup title="Request" tag="POST" label="/auth/login">
    ```bash {{ title: 'cURL' }}
    curl -X POST https://dev.openldr.org.mz/auth/login \
      -H "Content-Type: application/json" \
      -d '{
        "user_name": "your_username",
        "password": "your_password"
      }'
    ```

    ```python {{ title: 'Python' }}
    import requests

    response = requests.post(
        "https://dev.openldr.org.mz/auth/login",
        json={
            "user_name": "your_username",
            "password": "your_password"
        }
    )

    token = response.json()["access_token"]
    ```

    ```javascript {{ title: 'JavaScript' }}
    const response = await fetch('https://dev.openldr.org.mz/auth/login', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        user_name: 'your_username',
        password: 'your_password',
      }),
    })

    const { access_token } = await response.json()
    ```
    </CodeGroup>

```json {{ title: 'Response' }}
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```
  </Col>
</Row>

    Include the token in the `Authorization` header as a Bearer token. The API will return JSON data that you can use in your applications.
  </Col>
  <Col sticky>
    <CodeGroup title="Request" tag="GET" label="/hiv/vl/laboratories/tested_samples/">
    ```bash {{ title: 'cURL' }}
    curl https://dev.openldr.org.mz/hiv/vl/laboratories/tested_samples/ \
      -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
    ```

    ```python {{ title: 'Python' }}
    response = requests.get(
        "https://dev.openldr.org.mz/hiv/vl/laboratories/tested_samples/",
    ```

## Common parameters {{ tag: 'ALL', label: 'Query Parameters' }}

<Row>
  <Col>
    Most API endpoints accept a set of common query parameters for filtering and aggregating data. These parameters allow you to narrow down results by date range, geographic location, and level of detail.

    <Properties>
      <Property name="interval_dates" type="JSON array">
        Date range filter as a JSON array with two dates in `YYYY-MM-DD` format: `["2025-01-01","2025-12-31"]`. Defaults to the last 12 months if not provided.
      </Property>
      <Property name="province" type="string">
        Filter by province name. Supports multi-select by passing the parameter multiple times.
      </Property>
      <Property name="district" type="string">
        Filter by district name. Supports multi-select by passing the parameter multiple times.
      </Property>
      <Property name="health_facility" type="string">
        Filter by a specific health facility name.
      </Property>
      <Property name="facility_type" type="string">
        Grouping level for aggregated results. Accepted values: `"province"`, `"district"`, `"health_facility"`.
      </Property>
      <Property name="disaggregation" type="string">
        Enable or disable data disaggregation. Accepted values: `"True"` or `"False"`.
      </Property>
    </Properties>
  </Col>
  <Col sticky>
    <CodeGroup title="Request with parameters" tag="GET" label="/hiv/vl/laboratories/tested_samples/">
    ```bash {{ title: 'cURL' }}
    curl -G https://dev.openldr.org.mz/hiv/vl/laboratories/tested_samples/ \
      -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIs..." \
      --data-urlencode 'interval_dates=["2025-01-01","2025-12-31"]' \
      --data-urlencode "province=Maputo Cidade" \
      --data-urlencode "province=Gaza" \
      --data-urlencode "facility_type=district" \
      --data-urlencode "disaggregation=True"
    ```
    </CodeGroup>
  </Col>
</Row>

## Error handling

<Note>
  If you receive a `401 Unauthorized` response, your JWT token may have expired. Request a new token by calling the `/auth/login` endpoint again.
</Note>

The API uses standard HTTP status codes to indicate the success or failure of a request.

| Status Code | Description |
|-------------|-------------|
| `200` | **Success** — The request was processed successfully. |
| `401` | **Unauthorized** — The JWT token is missing, invalid, or expired. |
| `500` | **Server Error** — An unexpected error occurred on the server. |

```json {{ title: 'Error response' }}
{
  "error": "Unauthorized",
  "message": "Missing or invalid authentication token.",
  "status_code": 401
}
```
